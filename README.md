# דירומקס — ערכת עיצוב לוורדפרס

ערכת עיצוב (theme) מלאה לאתר דירומקס — תיווך, יזמות וניהול השבחת נכסים.
בנויה לפי העיצוב המאושר, לפי תקן הפיתוח של Multi Digital, ולפי ת"י 5568 ו-WCAG 2.2 AA.

בלי page builder, בלי תוסף טפסים, בלי jQuery, בלי ספריות צד ג' ובלי אף בקשה לשרת חיצוני.

## אזור אישי ותיקי לקוחות

תוסף נפרד, `diromax-portal`. לכל לקוח תיק דיגיטלי עם ההסכם, התקציב, ההוצאות, התשלומים, דרישות התשלום, המסמכים והעדכונים. הלקוח רואה את התיק בכתובת `/portal/`, ומקבל מייל מעוצב על כל עדכון.

- **רמת סיכון 3** (מידע פיננסי). המסמכים נשמרים מוצפנים, ונדרש אימות דו-שלבי למנהלים.
- **התקנה, הגדרות `wp-config.php` ומיפוי מידע:** [`diromax-portal/README.md`](diromax-portal/README.md)
- **אפיון:** [`docs/client-portal/spec.md`](docs/client-portal/spec.md) · **בדיקה:** [`docs/client-portal/verification.md`](docs/client-portal/verification.md)

הערכה מספקת לתוסף נקודת חיבור אחת: ה-filter `dx_nav_links`, שדרכו נוסף הקישור "אזור אישי" להדר.

## התקנה — 5 דקות

1. **העלאת הערכה** — להעלות את `dist/diromax.zip` ב*עיצוב ← ערכות עיצוב ← הוספה ← העלאת ערכה*, ולהפעיל.
   לבניית הקובץ מחדש אחרי שינוי בקוד:

   ```bash
   bash bin/build-zip.sh      # מריץ גם את בניית הקבצים המוקטנים
   ```

2. **יצירת העמודים** — *עמודים ← הוספה*, ולכל עמוד לבחור תבנית תחת *תכונות עמוד ← תבנית*:

   | כותרת העמוד | תבנית |
   |---|---|
   | ניהול השבחת נכסים | דירומקס — ניהול השבחת נכסים |
   | תיווך | דירומקס — תיווך |
   | שאלות ותשובות | דירומקס — שאלות ותשובות |
   | מאמרים | דירומקס — מאמרים |
   | צור קשר | דירומקס — צור קשר |
   | הצהרת נגישות | דירומקס — הצהרת נגישות |

   ואז *הגדרות ← קריאה ← עמוד ראשי קבוע* ← "ניהול השבחת נכסים".
   (או להשאיר ריק — `front-page.php` מציג את עמוד ההשבחה בכל מקרה.)

3. **פרטי קשר** — *התאמה אישית ← דירומקס — פרטי קשר*: טלפון, וואטסאפ (פורמט 972541234567), דוא״ל, אזור פעילות וכתובת לקבלת לידים.

4. **נגישות** — *התאמה אישית ← דירומקס — נגישות*: שם רכז/ת הנגישות, טלפון, דוא״ל ותאריך עדכון ההצהרה. הפרטים נכנסים אוטומטית לעמוד ההצהרה.

5. **תמונות ולוגו** — *התאמה אישית ← דירומקס — תצוגה*:
   - **תמונת הירו** לעמוד ההשבחה (פורטרט 3:4, מוצגת בשחור־לבן) והטקסט החלופי שלה.
   - **תמונת ברירת מחדל למאמרים** (יחס 8:5) — מוצגת בכרטיס המאמר, בראש המאמר ובשיתוף ברשתות בכל פוסט שאין לו תמונה ראשית. בלי הגדרה כזו נשאר הכיתוב האפור מהעיצוב.
   - הלוגו נמצא תחת *זהות האתר*.

6. **קישורים ידידותיים** — *הגדרות ← קישורים ידידותיים ← שם הפוסט*.

## עריכת הטקסטים

כל טקסט שמופיע באתר ניתן לעריכה מ**תוכן האתר** בתפריט הראשי של לוח הניהול — 127 שדות, מסודרים בשבע לשוניות לפי מבנה האתר:

| לשונית | מה יש בה |
|---|---|
| כללי | תפריט, כפתורים, סרגל תחתון, פוטר, עמוד 404 |
| עמוד השבחת נכסים | הירו, שמונת המקטעים, הפס הכחול, מקטע הסיום |
| עמוד תיווך | כותרות, פסקאות ושלושת השירותים |
| עמוד שאלות ותשובות | הכותרות וכל השאלות |
| עמוד מאמרים | כותרות והודעות ריקות |
| עמוד צור קשר | כותרות, תוויות השורות ותיבת "מה קורה אחרי" |
| טופס יצירת קשר | כותרות, תוויות שדות, כפתורים והודעות התודה |

איך זה עובד:

- **רשימות ניתנות להוספה ומחיקה** — כרטיסים, שלבי תהליך, שורות הטבלה, שאלות ותשובות ואפשרויות הבחירה בטופס. כל אחת עם כפתור "הוספת שורה" ו"מחיקה".
- **שבירת שורה בכותרות** — בשדות הכותרת כל שורה חדשה שתקלידו תוצג כשבירת שורה באתר, בלי לכתוב HTML.
- **נשמר רק מה ששיניתם.** שדה שלא נגעתם בו ממשיך לקחת את הטקסט מהערכה, ולא נשמר בבסיס הנתונים כלל. באתר טיפוסי מדובר בכמה מאות בתים, באפשרות `autoload=off` — כלומר אפס נטל על כל טעינת עמוד.
- **"החזרת המקטע לטקסט המקורי"** מוחק את השינויים בלשונית הנוכחית ומחזיר את ברירות המחדל של הערכה.

התוכן של המאמרים, העמודים המשפטיים והצהרת הנגישות נערך במקומות הרגילים של וורדפרס: *פוסטים* ו*עמודים*.

### אבטחה

- כל קלט עובר `sanitize_text_field` / `sanitize_textarea_field` / `sanitize_email` / `absint` / `sanitize_key`.
- כל פלט עובר `esc_html` / `esc_attr` / `esc_url` / `wp_kses`.
- Nonce בכל פעולה משנת נתונים; `check_admin_referer` בעורך התוכן; `current_user_can` לפני כל פעולה רגישה.
- `permission_callback` בנקודת ה-REST היחידה.
- השאילתה הישירה היחידה משתמשת ב-`$wpdb->prepare()`.
- ערכי `select` מאומתים מול רשימת האפשרויות שהטופס עצמו הציע — ולא מתקבלים כטקסט חופשי.
- כתובת המקור מתקבלת רק אם היא מצביעה על הדומיין של האתר; ההפניה היא `wp_safe_redirect`.
- Honeypot נגד ספאם + הגבלת קצב של 5 פניות לשעה לכל כתובת.
- **כתובת ה-IP לא נשמרת.** להגבלת הקצב נשמר Hash מלוח בלבד, שנמחק מעצמו בתום החלון.
- אין `eval`, `exec`, `shell_exec`, `system`, `passthru`, `base64_*`, ואין קוד מוצפן.

### תאימות למטמון

הטופס לא מסתמך על ה-nonce שהודפס ב-HTML: הסקריפט מושך nonce טרי מנקודת REST ברגע שנוגעים בטופס ראשון. כך עמוד ששוחזר ממטמון עמוד מלא (LiteSpeed, WP Rocket, Cloudflare) לא יכול לשלוח nonce שפג. ללא JavaScript הטופס עובד כ-POST רגיל עם הפניה חזרה והודעה.

### נגישות — ת"י 5568 ו-WCAG 2.2 AA

- **0 ליקויים ב-axe-core** על תשעת סוגי העמודים, בכל שלושת מצבי הצבע ועם הפאנל פתוח.
- כותרת H1 אחת בכל עמוד, היררכיית כותרות רציפה, HTML סמנטי, אפס מזהים כפולים.
- ניווט מלא במקלדת; קישור "דלג לתוכן"; אף רכיב ממוקד אינו מוסתר מאחורי הכותרת הדביקה.
- סרגל נגישות: הגדלה/הקטנה של טקסט, ניגודיות גבוהה, היפוך צבעים, גווני אפור, גופן קריא, ריווח מוגדל, הדגשת קישורים וכותרות, קו תחתון, עצירת אנימציות, סרגל קריאה, סימון מוגבר למקלדת ואיפוס. ההעדפות נשמרות ב-`localStorage` ומוחלות לפני הצביעה הראשונה.
- הפאנל הוא דיאלוג מודאלי אמיתי: לכידת מיקוד, סגירה ב-ESC, והחזרת המיקוד לכפתור הפותח.
- **מצבי הצבע ממומשים כהחלפת טוקנים ולא כ-`filter`** — פילטר על אלמנט השורש היה הופך אותו ל-containing block ושובר כל `position: fixed` בעמוד.
- כל יחסי הניגודיות נבדקו חישובית ועוברים 4.5:1 לטקסט רגיל ו-3:1 לרכיבי ממשק — בפלטה הרגילה ובכל אחד ממצבי הנגישות.
- אין גלילה אופקית ברוחב 320px ואין שבירה בהגדלת טקסט ל-160%.
- האקורדיון בנוי על `<details>` נטיבי; הטבלה הרחבה היא אזור ממוקד עם תווית משלו.
- `prefers-reduced-motion` מכובד.

### SEO

HTML סמנטי, H1 יחיד, Open Graph ו-Twitter Card, ו-JSON-LD: `RealEstateAgent`, `WebSite`, `BreadcrumbList`, `Article` ו-`FAQPage`. כשמותקן תוסף SEO (Yoast, Rank Math, SEOPress, AIOSEO, The SEO Framework) הערכה מפנה לו את הבמה ומשאירה רק את סכמת ה-FAQ, שמקורה בתוכן הערכה ולא בתוכן הפוסט.

## עבודה על הקוד

```bash
php bin/build-assets.php      # בנייה מחדש של הקבצים המוקטנים (ערכה ותוסף)
composer install              # כלי הפיתוח
composer lint                 # PHPCS (תוסף וערכה)
composer analyse              # PHPStan (תוסף וערכה, רמה 8)
composer test                 # PHPUnit: יחידה + אינטגרציה
```

- **CSS:** לערוך רק את `style.css` ואז לבנות. `style.min.css` הוא תוצר.
- **תוכן:** ברירות המחדל ב-`inc/content.php`, מקובצות לפי עמוד ונטענות רק כשצריך אותן. כל ערך עובר דרך `dx_content()` ומסונן ב-`apply_filters` — אפשר להעביר ל-ACF בלי לגעת בתבנית.
- **קידומות:** כל פונקציה, מחלקה, meta ו-CPT מתחילים ב-`dx_` / `dx-`.
- **RTL:** תכונות לוגיות בלבד — `padding-inline-start`, `border-inline-end`, `inset-inline`.
- **פלטה:** שלושה צבעים — כחול, לבן, כתום (+ טורקיז לפרטים ודיו לטקסט). צבעי טקסט הם טוקנים נפרדים (`--dx-orange-text`, `--dx-blue-text`) כי הכתום המקורי אינו קריא כטקסט על רקע בהיר.

### מה במכוון לא נעשה

- **בלי page builder.** הפריסה נזילה ומבוססת `auto-fit` + `clamp`; בילדר היה שובר את הגבולות של 2px ואת המרווחים.
- **בלי תוסף טפסים.** הטופס במקום, מאובטח, ונשמר בלוח הניהול. למעבר ל-CF7 מחליפים רק את `template-parts/lead-form.php`.
- **בלי אנימציות שלא בעיצוב.** אין fade-in-on-scroll, אין parallax, אין carousel.
- **בלי המצאת נתונים.** אין שנות ניסיון, אין מספר פרויקטים ואין היקפים כספיים.

## מה נשאר להשלמה על ידי הלקוח

1. פרטי קשר אמיתיים במקום `054-000-0000` ו-`info@diromax.co.il`.
2. פרטי רכז/ת הנגישות ותאריך עדכון ההצהרה.
3. תמונת הירו, תמונת ברירת מחדל למאמרים, ותמונות לפני/אחרי לפרויקטים.
4. לוגו סופי, אם ייבחר אחד חדש.
