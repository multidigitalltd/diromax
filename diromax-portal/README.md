# Diromax — אזור אישי ותיקי לקוחות

תוסף וורדפרס פרטי. לכל לקוח תיק דיגיטלי: ההסכם, התקציב, ההוצאות, התשלומים, דרישות התשלום, המסמכים ועדכוני ההתקדמות. הלקוח רואה את התיק באזור אישי באתר, ומקבל מייל מעוצב על כל עדכון.

**שלב 2:** לוח בקרה למנהל, תזכורות תשלום אוטומטיות, העדפת מיילים לכל לקוח (מיידי, סיכום יומי, בלי) וסיכום חודשי, החלטות לאישור הלקוח, אישור קריאת הסכם, ייצוא CSV, פתיחת תיק מליד, וכניסה עם סיסמה.

- **אפיון:** [`docs/client-portal/spec.md`](../docs/client-portal/spec.md)
- **תוצאות בדיקה:** [`docs/client-portal/verification.md`](../docs/client-portal/verification.md)
- **רמת סיכון: 3.** מידע פיננסי של לקוחות פרטיים (סעיף 3.1 בתקן). החריגות המאושרות מתועדות ב-[`EXCEPTIONS.md`](../EXCEPTIONS.md).

## דרישות

- PHP 8.3 ומעלה, עם ההרחבות sodium, intl ו-fileinfo.
- WordPress 6.8 ומעלה (נבדק על 7.1).
- MySQL 8 או MariaDB 10.11, עם טבלאות InnoDB.
- ערכת העיצוב של דירומקס. התוסף עובד גם בלעדיה, אבל ההדר והעיצוב מגיעים ממנה.

## התקנה

1. **מפתח הצפנה.** בלעדיו אי אפשר להעלות מסמכים. יוצרים מפתח אחד לאתר:

   ```bash
   php -r 'echo base64_encode(random_bytes(32)), PHP_EOL;'
   ```

   ומוסיפים ל-`wp-config.php`:

   ```php
   define( 'DX_PORTAL_KEY', 'הערך שיצא' );
   ```

   **את המפתח שומרים מיד במנהל הסיסמאות של המשרד.** מפתח שאבד פירושו שאי אפשר לפתוח אף מסמך שהועלה. לא שולחים אותו במייל או בצ'אט (סעיף 4.8 בתקן). פרטים ב"גיבוי המפתח" למטה.

2. **תיקיית המסמכים מחוץ לאתר (מומלץ).**

   ```php
   define( 'DX_PORTAL_PRIVATE_DIR', '/home/USER/dx-private' );
   ```

   בלי ההגדרה הזו, המסמכים נשמרים ב-`wp-content/uploads/dx-private`. ב-Apache וב-IIS התוסף חוסם את התיקייה בעצמו. **ב-Nginx חובה להוסיף:**

   ```nginx
   location ^~ /wp-content/uploads/dx-private/ { deny all; return 404; }
   ```

3. **מעלים את התיקייה `diromax-portal`** ל-`wp-content/plugins` ומפעילים. ההפעלה יוצרת את הטבלאות, את התפקידים ואת כתובות `/portal/`.

4. **הגדרות ← קישורים ידידותיים ← שמירה.** כך כתובות האזור האישי מתרעננות.

5. **Cron של השרת.** המיילים נשלחים מתור כל 5 דקות, ופעם ביום, אחרי שעת השליחה שבהגדרות (ברירת מחדל 09:00), יוצאים התזכורות, הסיכומים היומיים והסיכום החודשי. באתר עם מעט תנועה WP-Cron לא רץ בזמן (סעיף 16.4.7):

   ```php
   define( 'DISABLE_WP_CRON', true );
   ```

   ```bash
   */5 * * * * curl -s https://diromax.co.il/wp-cron.php?doing_wp_cron >/dev/null
   ```

6. **קוד כניסה במייל: מובנה, בלי תוסף.** כל כניסה עם סיסמה, של אנשי צוות בעמוד הכניסה של וורדפרס ושל לקוחות באזור האישי, מחייבת קוד בן 6 ספרות שנשלח למייל של החשבון (תקף 10 דקות, לכניסה אחת). קישור הכניסה במייל הוא עצמו האימות. **לא מתקינים Two Factor**, ולא מפעילים את מודול האימות של AIOS: שני אימותים זה על זה רק מבלבלים. אם אחד מהם פעיל, מופיעה הודעה במסכי התיקים.

   **תיבות המייל של הצוות חייבות אימות דו-שלבי משלהן** (ב-Google Workspace או ב-Microsoft 365): מי שמשתלט על תיבת המייל יכול לקבל את הקוד. זה תנאי של חריגה 5 ב-`EXCEPTIONS.md`.

   **מתג חירום**, כשהאתר לא מצליח לשלוח מיילים ואי אפשר להיכנס:

   ```php
   define( 'DX_PORTAL_EMAIL_CODE_OFF', true );
   ```

   כל כניסה בזמן הזה נרשמת ביומן השגיאות, ומסכי התיקים מציגים שגיאה עד שמוחקים את השורה.

   **ב-AIOS, אם מפעילים "Disallow unauthorized REST requests":** ערכת העיצוב כבר משאירה פתוח את נתיב הטופס של האתר (`diromax`), כדי שטופס יצירת הקשר ימשיך לעבוד. שינוי קידומת מסד הנתונים ב-AIOS עושים רק עם גיבוי מלא.

7. **מטמון.** האזור האישי שולח `Cache-Control: private, no-store` ומגדיר `DONOTCACHEPAGE`, ו-LiteSpeed מכבד את זה אוטומטית. בכל זאת מוסיפים החרגה של `/portal/*` ב-WP Rocket ובכלל מטמון של Cloudflare (Bypass cache).

8. **מיילים דרך Postmark.** כל המיילים של האתר יוצאים דרך Postmark: של האזור האישי, של טופס הלידים ושל וורדפרס עצמה. בלי תוסף SMTP. בלי מפתח, האתר שולח כמו קודם.

   **ב-Postmark:**
   1. **Sender Signatures ← Add Domain** עם הדומיין של האתר. מוסיפים ב-DNS את רשומת ה-DKIM ואת ה-Return-Path (CNAME) שמוצגות שם, ומחכים לאימות. רשומת DMARC לדומיין נשארת חובה (סעיף 4.13.15).
   2. **Servers ← השרת ← API Tokens:** מעתיקים את ה-Server API Token.
   3. **Default Inbound Stream ← Settings:** מעתיקים את כתובת הדואר הנכנס (`...@inbound.postmarkapp.com`). רשות: דומיין משנה משלכם לתשובות, למשל `reply.diromax.co.il`, עם רשומת MX אל `inbound.postmarkapp.com` בעדיפות 10, ואז הכתובת היא `reply@reply.diromax.co.il`.

   **בלוח הבקרה של התוסף:** *תיקי לקוחות ← הגדרות*, בחלק "שליחה וקבלה של מיילים". ממלאים את ה-Token, את כתובת השולח (מהדומיין המאומת) ואת כתובת הדואר הנכנס, ושומרים. רק מנהל מערכת רואה את החלק הזה.

   - **ה-Token נשמר מוצפן** במפתח של האתר (`DX_PORTAL_KEY`), ולא מוצג שוב, רק "שמור". שדה ריק בשמירה משאיר את הערך הקיים, והתיבה "למחוק" מוחקת אותו. אם `DX_PORTAL_KEY` לא מוגדר, אי אפשר לשמור סודות. אם המפתח הוחלף, המסך מבקש להזין את ה-Token מחדש.
   - **מפתח ה-webhook** נוצר בכפתור "יצירת מפתח webhook". הוא מוצג **פעם אחת בלבד**, כבר בתוך שתי הכתובות להדבקה ב-Postmark. במסד נשמר רק ה-hash שלו. מפתח חדש מבטל מיד את הקודם, ולכן אחרי יצירה מעדכנים את שתי הכתובות ב-Postmark.
   - **מי שמעדיף wp-config.php** יכול להמשיך: קבוע שמוגדר שם גובר, והשדה שלו נעול במסך. `DX_POSTMARK_TOKEN`, `DX_POSTMARK_FROM`, `DX_POSTMARK_STREAM`, `DX_POSTMARK_INBOUND`, `DX_POSTMARK_WEBHOOK_KEY` (32 תווים לפחות).
   - כל שמירה נרשמת ביומן הביקורת, עם שמות השדות שהשתנו בלבד, בלי הערכים. החריגה רשומה כחריגה 6 ב-`EXCEPTIONS.md`.

   **Webhooks ב-Postmark.** את שתי הכתובות מעתיקים מההודעה שמופיעה אחרי יצירת המפתח. שם המשתמש בהן הוא `postmark` והסיסמה היא המפתח, כתובים מיד אחרי `https://`:
   - **מיילים שחזרו:** בזרם היוצא (Default Transactional Stream) ← Webhooks ← Add webhook, הכתובת של `/wp-json/diromax-portal/v1/postmark/events`, ומסמנים Bounce ו-Spam Complaint.
   - **תשובות של לקוחות:** ב-Default Inbound Stream ← Settings ← Webhook, הכתובת של `/wp-json/diromax-portal/v1/postmark/inbound`.

   **בדיקה:** ב*הגדרות* של האזור האישי, "שליחת מייל בדיקה אליי". ב-Postmark, כפתור הבדיקה של ה-webhook צריך לקבל 200. אם מתקבל 401 עם הסיסמה הנכונה, השרת לא מעביר ל-PHP את הכותרת `Authorization`. ב-LiteSpeed זה עובד. ב-Apache עם PHP-FPM, הקובץ `.htaccess` הרגיל של וורדפרס כבר מעביר אותה. אם הוא שונה, מחזירים את השורה `RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]`.

   **Cloudflare:** הנתיב `/wp-json/diromax-portal/v1/postmark/` צריך לקבל בקשות POST מבחוץ, בלי אתגר (Challenge) או חסימת בוטים. ב-AIOS, גם כש-"Disallow unauthorized REST requests" מופעל, התוסף משאיר את הנתיב פתוח בעצמו. הסיסמה מגינה עליו.

   אם השליחה דרך Postmark נכשלת, גם קודי הכניסה לא יוצאים: מתג החירום שבסעיף 6.

9. **Turnstile (רשות, מומלץ).** ב*הגדרות*, בחלק "הגנה על טפסים (Cloudflare Turnstile)", ממלאים את ה-Site Key ואת ה-Secret Key מ-Cloudflare. מאותו רגע גם טופס הכניסה לאזור האישי וגם טופס הלידים של האתר מוגנים ב-Turnstile. ה-Secret Key נשמר מוצפן, כמו ה-Token של Postmark. גם כאן `DX_TURNSTILE_SITE_KEY` ו-`DX_TURNSTILE_SECRET_KEY` ב-wp-config.php גוברים, אם מוגדרים.

   **נשארים ב-wp-config.php בלבד:** `DX_PORTAL_KEY` (מפתח ההצפנה, שמצפין גם את הסודות שבמסך), `DX_PORTAL_PRIVATE_DIR` ו-`DX_PORTAL_EMAIL_CODE_OFF` (מתג החירום). מפתח שנשמר במסד ליד מה שהוא מצפין לא מגן על כלום, ומתג חירום צריך לעבוד גם כשאי אפשר להיכנס ללוח הבקרה.

## שימוש

| מי | איפה | מה |
|---|---|---|
| מנהל מערכת | *תיקי לקוחות*, *הגדרות* | לוח בקרה של כל המשרד, כל התיקים, שיוך מנהלי פרויקטים, הגדרות, מחיקת תיק |
| מנהל פרויקט (תפקיד "מנהל פרויקטים") | *תיקי לקוחות* | לוח בקרה ותיקים, רק של התיקים ששויכו אליו. פתיחת תיק, לקוחות, תקציב, תנועות, החלטות, עדכונים, מסמכים, ייצוא CSV |
| לקוח (תפקיד "לקוח אזור אישי") | `/portal/`, `/portal/account/` | רק התיקים שהוא חבר בהם, ורק מה שסומן "גלוי ללקוח". עונה על החלטות ומתכתב עם מנהל הפרויקט (בעלים ושותף, לא צופה), רואה את יומן הצילומים, מאשר קריאת הסכם, מוריד CSV, בוחר העדפת מיילים וסיסמה. אין לו גישה ללוח הניהול |

- **תיק לדוגמה:** בלוח הבקרה, "יצירת תיק לדוגמה". נוצר תיק מלא לניסיון: תקציב, תנועות, התחייבות, דרישת תשלום באיחור ודרישה פתוחה, עדכונים והחלטה שממתינה ללקוח. אין בו לקוחות, ולכן לא נשלח שום מייל. כדי לנסות את האזור האישי, מוסיפים בלשונית "לקוחות" כתובת מייל נוספת שלכם. מוחקים אותו כמו כל תיק: מנהל מערכת, בלשונית "פרטים".
- **טלפון של מנהל הפרויקט:** בעמוד הפרופיל, בשדה "טלפון שמוצג ללקוחות". הלקוח רואה אותו בכרטיס "מנהל הפרויקט שלך", כטקסט וכקישור חיוג. ריק: הטלפון הכללי של האתר, עם התווית "טלפון המשרד".
- **תקציב, סעיפים וסעיפי משנה:** תבנית ברירת המחדל נמצאת ב*הגדרות*, "תקציב ברירת מחדל לתיק חדש": סעיף בכל שורה, וסעיף משנה בשורה שמתחילה במקף. כל תיק חדש מתחיל ממנה, ובלשונית "תקציב" של התיק משנים בחופשיות: שמות, סכומים, הוספה, מחיקה וסדר. תנועה נרשמת לסעיף או לסעיף משנה.
- **פגישות:** בלשונית "פגישות" בתיק. מסמנים אילו לקוחות מוזמנים, והם מקבלים הזמנה ליומן במייל ורואים את הפגישה באזור האישי. תזכורות נשלחות יום לפני ובבוקר של יום הפגישה, בשעת הריצה היומית שבהגדרות.
- **תחזית תשלומים:** למנהל מערכת, בתפריט "תחזית תשלומים": דרישות פתוחות לפי חודש, איחורים, ותקציב מול ביצוע בכל תיק, עם הורדה ל-CSV.
- **תוכנית תשלומים:** בלשונית "תוכנית תשלומים" בתיק. כל תשלום מגיע בסיום שלב, בתאריך או ידנית, בסכום קבוע או באחוז מהבסיס (סך התקציב, או סכום שקובעים לתיק). כשהוא מגיע נוצרת טיוטה, ורק אחרי אישור המנהל היא נשלחת ללקוח כדרישת תשלום. את התבנית לתיק חדש קובעים ב*הגדרות*, תחת "תוכנית תשלומים לתיק חדש".
- **לוח זמנים:** בלשונית "לוח זמנים" בתיק קובעים התחלה וסיום מתוכננים לכל שלב, ואבני דרך. הלקוח רואה את הלוח (תוכנית מול ביצוע) רק אחרי שמסמנים "להציג ללקוח". תאריך שזז מוצג לו עם המקורי ועם ההסבר שכותבים, ומייל נשלח רק כשמסמנים "לשלוח ללקוח מייל". את המשך הטיפוסי של כל שלב קובעים ב*הגדרות*, ובתיק מחשבים ממנו את התאריכים מתאריך התחלה.
- **מחיקת תיק:** מנהל מערכת, בכל תיק, בלשונית "פרטים" (או "מחיקה" ברשימת התיקים). המסך מראה מה יימחק, כולל חשבונות לקוח שאין להם תיק אחר ויימחקו גם הם. מקלידים את מספר התיק לאישור. אי אפשר לשחזר: קודם מורידים CSV ושומרים דוח.
- **פתיחת תיק מליד:** ברשימת הלידים של ערכת העיצוב, "פתיחת תיק" ליד כל ליד. נדרשת גם הרשאה לערוך את הליד (מנהל מערכת או עורך).
- **סיסמה:** רק ללקוחות. אנשי צוות נכנסים דרך וורדפרס. בשני המקרים, אחרי הסיסמה מקלידים קוד שנשלח למייל. "שכחתי סיסמה" = קישור כניסה למייל.
- **הקישור "אזור אישי" בהדר** מתווסף אוטומטית. כדי להסתיר אותו: `add_filter( 'dx_portal_show_nav_link', '__return_false' );`

## ניהול מהאתר, בלי לוח הבקרה של וורדפרס

`/portal/manage/` הוא מסך הניהול כאפליקציה באתר: לוח בקרה, תיקים עם חיפוש, לוח שלבים, תיק מלא על כל הלשוניות, תיק חדש, והגדרות (למנהל מערכת). העיצוב והפעולות זהים ללוח הניהול, וזה עובד גם בטלפון.

- **כניסה:** דרך עמוד הכניסה של וורדפרס: סיסמה, ואז קוד מהמייל. מנהל פרויקט שנכנס מגיע ישר לאפליקציה. מנהל מערכת מגיע ללוח של וורדפרס, ויש לו קישור "מסך מלא באתר".
- **אפליקציה בטלפון:** בכרום (אנדרואיד) תפריט ← "הוספה למסך הבית". בספארי (אייפון) כפתור השיתוף ← "הוספה למסך הבית". נפתח במסך מלא עם האייקון של דירומקס.
- **כמה שלבים במקביל:** בלשונית "פרטי התיק" בוחרים לכל שלב סטטוס: טרם התחיל, בתהליך, הושלם או לא רלוונטי. אפשר לסמן כמה שלבים "בתהליך" יחד. בעדכון התקדמות בוחרים אם השלבים שלפני השלב החדש הושלמו, או שהוא מתחיל במקביל.
- **לוח שלבים:** כל התיקים הפעילים מסודרים לפי השלב שבו הם נמצאים, עם מספר הימים בשלב. תיק בכמה שלבים מופיע בכל אחד מהם.
- **הצעדים הבאים:** בסקירת כל תיק חדש יש רשימת הקמה עם קישור לכל צעד, עד שהכל הושלם.
- **מלוח הבקרה:** ליד כל דרישת תשלום באיחור או בשבוע הקרוב: "תזכורת" ו"סימון כשולמה".
- **סינון תנועות** לפי סוג וטקסט בלשונית הכספים.
- **הוספה מהירה:** בכל תיק יש כפתורים "+ תנועה", "+ עדכון", "+ מסמך" ו"+ החלטה". הם פותחים את הטופס המתאים, והסמן כבר בשדה הראשון.
- **צילומים מהשטח:** "+ צילומים" בכל תיק. מעלים עד 20 צילומים בפעם אחת, גם מהטלפון, עם שלב, תאריך וכיתוב, ובוחרים אם הם גלויים ללקוח. הלקוח רואה אותם בלשונית "יומן צילומים".
- **הודעות:** בלשונית "הודעות" בתיק רואים את השיחה עם הלקוחות ועונים. כל לקוח שמקבל מיילים מקבל את התשובה כולה במייל. הודעות חדשות מלקוחות מופיעות בלוח הבקרה עד שעונים עליהן.
- **חיפוש:** בשורה העליונה, לפי כתובת או מספר תיק.
- **אבטחה:** אותן בדיקות הרשאה, אותן פעולות ואותם אסימוני CSRF כמו בלוח הניהול. לקוח שמגיע לכתובת מועבר לאזור האישי שלו. תיק של מנהל אחר עונה 404.
- **לידים** נשארים בלוח של וורדפרס, כי הם חלק מערכת העיצוב. הקישור "לידים" בתפריט מוביל לשם.

## חתימות, מסמכים מהלקוח ומשימות (גרסה 1.6.0)

- **חתימה דיגיטלית:** הסכם, מסמך שסומן "לחתימת הלקוח" בהעלאה, ואישור החלטה. לקוח מחובר חותם באזור האישי בשם מלא וציור. לכל אחד אחר שולחים קישור מלשונית "הסכם ומסמכים", בטופס "שליחת מסמך לחתימה במייל". הקישור תקף 14 יום, לחתימה אחת, ומחייב קוד חד-פעמי למייל ותעודת זהות. ליד מסמך חתום יש "אישור חתימה" להדפסה. זו חתימה אלקטרונית פשוטה של המערכת, לא חתימה מאושרת של ספק חיצוני.
- **בקשת מסמך:** בלשונית "הסכם ומסמכים" → "בקשת מסמך מהלקוח". הלקוח מקבל מייל ומעלה מהאזור האישי.
- **דוח:** הלקוח והמנהל פותחים "דוח מלא לשמירה כ-PDF" מלשונית הכספים באזור האישי, ושומרים כ-PDF מחלון ההדפסה.
- **יעדים לשלבים:** בלשונית "פרטי התיק", שדה "יעד" ליד כל שלב.
- **משימות:** לשונית "משימות" בכל תיק. "המשימות שלי" בלוח הבקרה, וסיכום בוקר במייל (אפשר לכבות בהגדרות).

## גיבוי המפתח

- **מה המפתח מצפין:** רק את הקבצים שהועלו (הסכמים, חשבוניות, תמונות). הסכומים, התנועות והעדכונים לא מוצפנים, ולא תלויים במפתח.
- **מפתח שאבד:** אי אפשר לפתוח אף מסמך שהועלה עד אז, גם לא אנחנו. זו בדיוק ההגנה: מי שגונב את השרת או הגיבוי בלי המפתח לא יכול לקרוא את המסמכים. מפתח חדש יעבוד רק למסמכים שיועלו מעכשיו.
- **הגנה מטעות:** התוסף זוכר את טביעת האצבע של המפתח שאיתו הועלו המסמכים. אם המפתח ב-`wp-config.php` מוחלף כשכבר יש מסמכים, מופיעה התראה אדומה וההעלאה נחסמת, כדי שלא יתערבבו שני מפתחות. מחזירים את המפתח הקודם, וזה נפתר.
- **איך בודקים שהעותק השמור נכון:** במסך ההגדרות מופיעה טביעת האצבע של המפתח הנוכחי (12 תווים). מריצים על העותק השמור:

  ```bash
  php -r 'echo substr(hash_hmac("sha256", "dx-portal-fingerprint", base64_decode($argv[1])), 0, 12), PHP_EOL;' 'המפתח השמור'
  ```

  אותה טביעה = העותק נכון.
- **איפה שומרים:** במנהל הסיסמאות של המשרד, ועוד עותק אחד במקום נפרד (למשל מודפס בכספת). לא באותו שרת ולא באותו גיבוי של האתר.

## הסרה

כיבוי התוסף עוצר את המשימות המתוזמנות, והנתונים נשארים. מחיקת התוסף מסירה את התפקידים ואת המשימות, **אבל לא את הטבלאות ואת המסמכים**: אלה רשומות עסקיות שחלה עליהן חובת שמירה (חריגה 3 ב-`EXCEPTIONS.md`). מחיקה מלאה מחייבת להגדיר קודם:

```php
define( 'DX_PORTAL_PURGE_ON_UNINSTALL', true );
```

## פיתוח

הכלים משותפים לכל המאגר, ב-`composer.json` שבשורש:

```bash
composer install
composer lint          # PHPCS: WordPress-Extra, WordPress-Docs, PHPCompatibilityWP
composer analyse       # PHPStan רמה 8
composer test:unit     # בדיקות יחידה, בלי מסד נתונים
composer test          # יחידה + אינטגרציה (מסד בדיקות MySQL, ראו phpunit.xml.dist)
php bin/build-assets.php
```

בדיקות קצה-לקצה (וורדפרס זמני, Chromium ו-axe):

```bash
bash diromax-portal/tests/e2e/setup.sh /tmp/dx-e2e
cd diromax-portal/tests/e2e && npm ci --ignore-scripts
node client.e2e.js /tmp/dx-e2e && node manager.e2e.js /tmp/dx-e2e && node phase2.e2e.js /tmp/dx-e2e && node theme.e2e.js /tmp/dx-e2e
```
